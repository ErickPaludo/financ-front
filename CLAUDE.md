# FinancHub (financproject)

Front-end de gestão financeira pessoal: React 19 + Vite 8 + TypeScript, com MUI 9 (`@mui/material`, `@mui/icons-material`, Emotion). Back-end .NET separado (não está neste repositório) em `https://api.pldprojects.com.br/api` (produção; em dev, local em `https://localhost:7147`).

## Comandos

- Antes do primeiro `dev`/`build`: crie `.env.development` e `.env.production` a partir do `.env.example` (`VITE_API_URL`). Os `.env*` ficam fora do git; sem a variável o app para com erro claro. Nada de segredo neles: `VITE_*` vai para o navegador.
- `npm version patch|minor|major` — versão do front (única fonte: `package.json`; o `vite.config.ts` injeta como `__APP_VERSION__`, exibida no fim da barra lateral).
  - Com alterações não commitadas o `npm version` recusa: use `npm version <versão> --no-git-tag-version` e faça commit + `git tag v<versão>` depois. Tag simples não sobe com `--follow-tags`: `git push origin v<versão>`.
  - Publicar: `npm run deploy` (build + `gh-pages -d dist`, branch `gh-pages`). Ainda não confirmado se é assim que o site em produção é publicado: o branch `gh-pages` só passou a existir no deploy da 1.0.2-alpha (22/11/2026). Pergunte ao usuário antes de rodar.
- Release notes de cada versão: `RELEASE_NOTES_v<versão>.md` na raiz + a entrada da versão em `painel-novidades/novidades.ts`. Escritas para o **usuário final**, sem termos técnicos (pedido do usuário). Função experimental: diga que é experimental e o caminho para ligar (Opções de usuário › Experimental › Funções experimentais). Mudança depois do `npm version` sem subir a versão entra nas notas da versão atual.
- Não versione arquivos de teste com dados reais (ex.: `Nubank_*.csv` na raiz, fatura real usada para testar o Importar CSV).
- `npm run dev` — servidor de desenvolvimento (o Vite faz proxy de `/api` para o back-end).
- `npm run build` — `tsc -b` + `vite build` + copia `dist/index.html` para `dist/404.html` (fallback de rotas no GitHub Pages).
- `npx tsc -b --noEmit` — checagem de tipos. Rode antes de dar algo por pronto.
- `npm run lint` — ESLint. Passa sem erros: mantenha assim.
  - Busca ao abrir a tela: chame a API com `.then(...)` dentro do `useEffect` (a regra `set-state-in-effect` não aceita `async/await` direto no efeito). Formulário de edição dentro de gaveta: inicie o `useState` com os dados em vez de copiar num efeito (a gaveta remonta o conteúdo a cada abertura).
  - As funções do `ContaContext` são estáveis (`useMemo`); podem ir nas dependências sem causar loop.

## Direção do projeto

**Estamos migrando dos componentes feitos à mão com CSS próprio para o MUI, tela por tela.** Ao mexer numa tela:

- Use componentes do MUI (`Box`, `Stack`, `Typography`, `Button`, `Card`, `Drawer`, `Menu`, `Alert`, `Tooltip`…). Os antigos de texto (`TitleText`, `SubtitleText`, `LabelText`, `ErrorText`, `MsgTextBox`) foram removidos: título de tela é `TituloPagina`, título de gaveta é o `titulo` do `Modal`, erro é `<Alert severity="error">`.
- Algo repetido em mais de um lugar vira componente, hook ou utilitário (ver Estrutura). Nomes em português (props inclusive: `rotulo`, `valor`/`setValor`, `aberto`); `onClose`/`onClick` seguem a convenção do React/MUI.
- Apague o CSS que ficar sem uso. Classe usada por um só componente fica no CSS dele; só vai para `src/index.css` se mais de um componente usar.
- No MUI 9 não existem mais props de estilo soltas no `Stack`/`Box` (ex.: `alignItems`); use `sx`.
- Prefira cores do tema (`"primary.main"`, `"text.secondary"`, `"divider"`, `"background.paper"`) ou da paleta (`src/cores.ts`). Nada de hex solto em componente novo.

Telas **já migradas**: Login, Registrar, Inicial (resumo + cards de conta + gaveta de nova conta), barra lateral, carregamento, Categorias (gaveta), Movimentações, painéis de membros, de usuário, de convites e de agendadas. Não há mais telas com CSS próprio de cores fixas (sobram `LayoutPrincipal.css`, `Inicial.css`, `Movimentacoes.css` (também importado pelo Dashboard) e o do login).
Campos: sempre `CampoTexto` (ou `CampoDataHora` para data). `InputPrice` (`valor: number`/`setValor`; zerado fica vazio), `InputSelect` (`CampoTexto` com `select`; opções `{ rotulo, valor }`), `InputCheckBox` (`rotulo`/`marcado`/`setMarcado`) e `CheckBoxList` (`CampoTexto` só leitura + `Popover` com busca e `Checkbox`; `chaveId`/`chaveTexto`/`setSelecionados`; os marcados ao abrir vêm primeiro, e a ordem só muda ao reabrir, para o item não pular sob o mouse) usam componentes do MUI por dentro. Não crie `<input>`/`<select>` nativos com CSS próprio.

## Rotas (BrowserRouter, sem prefixo `/financproject`)

| Rota | Tela | Observação |
|---|---|---|
| `/login` | Login | redireciona para `/` se já houver usuário |
| `/registrar` | Registrar | |
| `/` | Inicial (antiga Home/Contas) | dentro do `LayoutPrincipal`; o endereço antigo `/inicial` redireciona para cá |
| `/:idConta/dashboard` | Dashboard | gráficos da conta; mesmos filtros na URL da tela de transações (período, categorias, status, tipo: `useFiltrosUrl` + `FiltrosConta`, sem a busca por texto) e **o mesmo GET** da tabela (`rotaMovimentacoes(idConta, filtros)` em `filtrosUrl.ts`); o único filtro no cliente é o campo "Ignorar categorias" (também na tela da conta, ver Tela da conta; props `ignoradas`/`setIgnoradas` do `FiltrosConta`, no painel abaixo de Categorias, com chips "Ignorando: …" na barra; vale na hora, como a busca por texto): tira só a categoria ignorada de cada movimentação (`semCategoriasIgnoradas` em `agrupamento.ts`: A e B, ignorando B, fica só A; sai inteira só a que ficou sem nenhuma categoria); a escolha fica em `dashboardIgnoradas:<idConta>`; os links da conta e do Dashboard na barra levam os filtros da URL junto (`manterFiltros`); com Tipo = Entrada/Saída só a pizza e a linha daquele tipo aparecem; subtópico "Dashboard" da conta na barra |
| `/:idConta/contabancaria` | Movimentacoes | `ContaDaRota` busca a conta pelo id da URL (recarregar funciona); inexistente/inativa/sem acesso volta para `/` |
| `*` | → `/login` | |

A conta selecionada (`ContaContext`) fica só em memória: a tela da conta busca pela URL (`ContaDaRota`), então recarregar funciona. Sem sessão (sem usuário salvo e sem token), o `LayoutPrincipal` redireciona para `/login`.

## API e autenticação

- Contrato da API (rotas, métodos, DTOs): Swagger em `https://api.pldprojects.com.br/swagger/v1/swagger.json` (rotas com prefixo `/api`). Confira nele antes de mudar uma chamada.

- `services/api/api.ts` guarda o access token fora do React e coloca `Authorization: Bearer` em toda requisição.
- Em **401**: chama `POST /Autenticacao/refresh` (cookie httpOnly `refreshToken`) **uma vez**, compartilhada entre requisições simultâneas, e repete a original. Se o refresh falhar, `AuthContext` faz logout e navega para `/login`. O refresh usa uma instância axios sem interceptors.
- `Conecta` devolve `{ sucesso, dados?, erro?, status? }`; quando o servidor não responde, `erro` vem com a mensagem do axios. Verifique `!resposta.sucesso`, não só `resposta.erro`.
- Datas: envie sempre UTC de verdade com `paraIsoUtc` (cadastro, conclusão, agendadas **e filtros**, via `parametrosApi`). Os filtros mandavam o horário local com "Z" (deslocava o período 3h).
- Lista vazia: a API responde **404** com mensagem ("Nenhum convite foi encontrado!") em vez de `[]`. O `useBuscaApi` trata 404 como lista vazia (sem erro) e, em qualquer falha, limpa os dados anteriores (senão o item recém-removido continuava na tela).
- `baseURL` vem de `VITE_API_URL`: em dev `/api` (proxy do Vite, cookie first-party), no build `https://api.pldprojects.com.br/api`. Em produção cross-site o back-end precisa marcar o cookie como `SameSite=None; Secure; Partitioned`.

## Tema, cores e modo claro/escuro

- `src/cores.ts`: `Paleta` com `primaria`, `secundaria`, `fundo`, `borda`, `texto`, `barraLateral` (cores próprias da barra) e `login` (variáveis `--fnc-login-*` do `LayoutAutenticacao.css`). `Cores` = paleta escura (para o que ainda é só escuro).
- Cor primária: `#155dfc`. Itens selecionados, botões de ação e o card de resumo usam a primária **sólida**; não há mais degradê (o `Button` `contained` usa a primária do tema).
- Modo claro/escuro: `useModoCor` (chave `modoCor`; sem escolha salva, segue o sistema). O `LayoutPrincipal` controla o modo; o botão fica no menu do usuário da barra lateral.
  - Só as rotas de `telaDeCards` (`LayoutPrincipal.tsx`: `/` e `/:idConta/contabancaria`) recebem o tema claro (e o fundo desfocado); os painéis e a gaveta seguem o modo em qualquer tela; as demais ficam no escuro até migrarem.
  - Componentes antigos com CSS próprio usam variáveis `--fnc-*` geradas de `paleta.telas` (`variaveisTelas` em `cores.ts`), aplicadas no `<main>` (paleta do modo) e na gaveta `Modal` (paleta do modo, como a barra). `--fnc-texto`/`--fnc-apoio` são para o que fica sobre o fundo azul da página; o texto das tabelas usa `--fnc-texto-superficie`. O label do `TextField` e do checkbox também lê `--fnc-apoio`. Não use hex nesses CSS.
  - Fundo da área central: `telas.pagina` + marca d'água (`.fnc-fundo-marca` em `index.css`). No escuro, igual ao login (`#030a1f`, marca branca, texto claro); no claro, **branco gelo** (`#eaf0f7`, os cards brancos se destacam) com a marca azul-escura (`.fnc-fundo-marca--escura`) e `--fnc-texto`/`--fnc-apoio` escuros (cards e tabelas continuam azuis com texto branco). O fundo fica no invólucro `.area-central`; em `/` e `/:idConta/contabancaria` o `<main>` ganha `.fundo-desfocado` (`backdrop-filter: blur(12px)`), que desfoca só o fundo, não o conteúdo.
  - Barra lateral: **branca** no modo claro em todas as telas (`BarraLateralClara` em `cores.ts`), `#0f172b` no escuro. A gaveta `Modal` segue a barra: no claro, `BarraLateralClara` + tema claro + `variaveisTelas(CoresClaro)`; no escuro, `CoresEscuro.barraLateral` + tema escuro.
- Logos em `src/assets/`: `pldprojects-logo-clara.svg` (login no escuro); na barra lateral só o SVG, sem quadro: `pldprojects-logo-azul.svg` no claro e `pldprojects-logo-azul-clara.svg` no escuro, `pldprojects-logo-azul-clara.svg` (toda branca, no carregamento sobre fundo escuro), `pldprojects-logo-azul.svg` (login e carregamento no modo claro; também a marca d'água do fundo claro, a 7% via `::before`), `pldprojects-marca-dagua.svg` (marca d'água do fundo escuro). A logo da barra sobe 10% (`translateY(-10%)`) porque o desenho pesa embaixo.
- Bordas arredondadas com fundo: use `backgroundClip: "padding-box"` (ou fundo e borda no mesmo elemento) para evitar serrilhado nos cantos — foi o caso dos campos de texto e da logo.

## Componentes-chave

- **Modal** (`componentes/modal`): todo modal de formulário é a gaveta MUI da direita (`Drawer`, 450px, cores e modo da barra lateral), com `aberto`, botão de fechar e `titulo` opcional (o título do formulário vai aqui, não dentro dele). Não crie overlays próprios. O conteúdo ainda renderiza durante a animação de fechar: guarde o item editado até lá (ex.: o `EditMembro` guarda o último membro exibido).
- **MsgBox** (`props/msg-box`): `tipo="aviso"` (Ok) ou `"pergunta"` (Sim/Não) num `Dialog` do MUI; `aoResponder(sim)`; fechar sem responder = "Não".
- **Estado entre telas**: só a conta selecionada e o vínculo do usuário com ela ficam em contexto (`ContaContext`). Dados de um formulário (movimentação editada, membro, convite) vão por props.
- **PainelLateral** (`componentes/painel-lateral`): esqueleto dos subpainéis colados à barra lateral (`Drawer` `persistent`, 340px ou `largura`, sem passar da tela; `deslocamento` = largura da barra; no celular ocupa a tela), com `CabecalhoPainel` (avatar, título, subtítulo, `onAtualizar` desenha o botão de atualizar, fechar), `EstadoLista` (erro, carregando e lista vazia) e `DetalhePainel` (ícone + texto nas linhas). Sem fundo escuro: a barra continua clicável; fecha no X, com Esc ou navegando pelo menu (`irPara`). O conteúdo desmonta ao fechar (`unmountOnExit`). Cores da barra (`useCoresBarra()` / `coresDaBarra(claro)` em `cores.ts`, também usadas pela barra e pelo `Modal`). A barra tem **um** `PainelLateral` e troca o conteúdo pela tabela `PAINEIS` em `BarraLateral.tsx` (`rotulo`, `Conteudo`, `daConta`, `largura`); cada painel exporta só o conteúdo (`React.FC<{ onClose }>`). Painel novo: um arquivo com o conteúdo + uma entrada em `PAINEIS` + o botão que chama `alternarPainel`.
- **PainelUsuario** (`componentes/painel-usuario`): "Opções de usuário" no menu do usuário abre este painel (substituiu a antiga tela `/usuario`): nome e e-mail no cabeçalho e as opções separadas por tópico (`Topico`, com `TituloSecao`). Cada opção é uma `OpcaoExpansivel` (ícone, título, descrição; expande o conteúdo abaixo, uma por vez). Tópico **Segurança** → "Alterar senha" (`FormularioSenha`: `POST /Usuarios/alterar_senha` com `{ senhaAntiga, senhaNova }`, igual ao `AlterarSenhaDTO` do Swagger (conferido em 22/11/2026); houve relato de erro na chamada ainda sem diagnóstico (falta o status/resposta da API); validação nos campos; depois de alterar, revoga a sessão e vai para `/login`). Tópico **Experimental** → "Funções experimentais" (Switch; `useExperimentais`, chave `funcoesExperimentais`, compartilhado entre painel e telas via `useSyncExternalStore`): hoje libera o "Importar CSV" e o "Exportar" da tela da conta. Opção nova: acrescente ao tipo `Opcao` e a um tópico.
- **PainelAgendadas** (`componentes/painel-agendadas`): **desativado** (sem entrada na barra nem em `PAINEIS`; o código continua na pasta). Quando ativo, o subtópico "Agendadas" da conta abria este painel largo (`largura` 920 no `PainelLateral`, limitado à tela), que substituiu a antiga tela `/agendadas`. Tabela (`TabelaDados`, preferências em `movimentacoes-fixas`) com "Nova agendada"; clicar numa linha edita. O formulário (`FormularioAgendada`, só MUI) abre na gaveta `Modal`: recorrência (por enquanto só mensal), datas, tipo, título, valor, observação, categorias; na edição, Excluir. As datas das agendadas vêm 3h à frente da API (`paraHorarioBrasilia`).
- **PainelConvites** (`componentes/painel-convites`): "Convites" no menu da barra abre este painel (substituiu a antiga tela `/convites`). Abas Recebidos (com a contagem de pendentes) e Enviados; cada convite é uma linha (iniciais da conta, de/para, acesso, situação, datas). Ações só enquanto pendente: Aceitar (direto), Recusar e Revogar (confirmam com `MsgBox`). Depois de responder, `contasAlteradas()` e rebusca.   - `permitirLinhas` mostra o botão que alterna para `LinhasSeparadas` (mesmo arquivo de pasta: cada linha é um card, nome da coluna acima do valor; mesmas colunas visíveis e ordenação, que muda pelo botão "Ordenar por" acima dos cards (menu com as colunas visíveis; a coluna já escolhida inverte a direção; "Redefinir ordenação" volta à `ordenacaoPadrao`); colunas com o mesmo `grupo` ficam uma abaixo da outra no card (ex.: Usu. cad./Usu. exe.); `sx` em `estilos.linhas`, classes `.linha-separada`/`.linha-separada-rotulo`; a caixa de seleção fica à esquerda, centralizada na altura do card, e o "Selecionar tudo" no mesmo recuo; até 600px (`CONSULTA_ESTREITA`) menos respiro e colunas de no mínimo 110px em vez de 150px, para caberem duas por linha em 380px). Usado só na tela da conta. Com a barra superior (até 768px, `CONSULTA_CELULAR` em `estilos.ts`) as linhas separadas são forçadas e o botão some (a preferência salva não muda).
  - Com `idPreferencias`, o botão "Salvar" (cor primária só com alteração não salva) grava ordem, colunas ocultas e ordenação em `tabela:<id>`. O formato (linhas separadas ligadas) é gravado na hora em `linhasSeparadas:<id>`. Lógica pura em `preferenciasTabela.ts`, testada por `scripts/testa-preferencias-tabela.ts` (`node --experimental-strip-types`).
- **TabelaMovimentacao** (`telas/movimentacoes/tabela`): `TabelaDados` com as colunas da movimentação (chips de categoria, valor colorido); clicar na linha (só quem edita; para o visualizador a linha não abre nada) abre `ConclusaoMovimentacao` num `Dialog` do MUI (concluir/extornar, deletar, alterar; "Copiar": troca o conteúdo pelo campo "Data da cópia" + `CampoRepetir` e faz um POST por mês com os mesmos dados, sempre pendentes, continuando da que falhou como no cadastro); "Alterar" abre o `CadMov` na gaveta `Modal` com a prop `movimentacao` (sem ela, o `CadMov` cadastra). Movimentação virtual (id 0, de agendamento) é materializada antes de concluir/deletar/editar (`materializarMovimentacao`). **Ações em massa** (só quem pode editar, prop `podeEditar`): os checkboxes só aparecem pelo botão de ícone "Selecionar várias" (`checklist`, na barra da tabela; ligado fica primário com X, e desligar desmarca tudo); marcando linhas aparece "Selecionadas (N)" junto dos ícones da barra (no celular só ícone + N; o grupo de ícones do `TabelaDados` quebra por dentro em vez de vazar), com o menu Concluir / Extornar / Alterar data / Alterar valor / Alterar categorias / Excluir (Alterar valor: `InputPrice`, todas as marcadas recebem o mesmo valor, PATCH só com `valor`, `alterarValorMovimentacao`; o tipo não muda, então o sinal continua; zerado não envia; a que já tem o valor conta como feita sem requisição; pedido do usuário), cada um com quantas vai mudar (Alterar data: todas as marcadas recebem a mesma data de movimentação, PATCH só com `dthrMovimentacao`, `alterarDataMovimentacao`; o campo começa no dia do início do filtro às 08:00 (`useFiltrosUrl`) e tem o botão "Agora" (data e hora atuais); "O que mudar" = "Só o dia" troca só o dia de cada uma, mantendo mês, ano e hora (`comDia` em `acoes-em-massa/dataEmMassa.ts`: dia que o mês não tem vira o último dia dele; testada por `scripts/testa-data-em-massa.ts`; a que já está no dia conta como feita sem requisição); pedido do usuário; Alterar categorias: "O que fazer" Adicionar às atuais / Remover das atuais / Substituir as atuais + `CheckBoxList` das categorias da conta, regra pura `categoriasResultantes` em `acoes-em-massa/categoriasEmMassa.ts` (testada por `scripts/testa-categorias-em-massa.ts`), PUT da lista inteira por `alterarCategorias`; a que já ficaria igual conta como feita sem requisição; substituir sem nenhuma escolhida deixa todas sem categoria, com aviso): concluir só as pendentes, extornar só as concluídas (as outras ficam como estão e o diálogo avisa; sem nenhuma, o item fica desabilitado). `AcaoEmMassa` (`telas/movimentacoes/acoes-em-massa`) mostra as opções da ação (concluir: agora ou "a data de cada movimentação") e, no botão da ação, pede confirmação num `MsgBox` "Tem certeza?" (Sim/Não, com o valor ou a data escolhidos e, ao excluir, "não pode ser desfeito"; vale para toda ação em massa, pedido do usuário), executa **uma por vez** (`removerMovimentacao`/`concluirMovimentacao`/`extornarMovimentacao` no `movimentacaoService`; materializam a virtual antes) com barra de progresso "N de M" (não fecha até acabar) e no fim mostra quantas deram certo e, para cada falha, título, data e a mensagem da API. As que falharam continuam marcadas; se alguma mudou, rebusca.
- **useEnvioFormulario(acao)**: controla `enviando`, `erro` e `tentouEnviar`; a ação devolve a mensagem de erro geral ou nada.
- **ListaPesquisa** (`componentes/lista-pesquisa`): `Paper` com pesquisa (`CampoTexto`, ignora maiúsculas e acentos), contagem ("n itens" / "n de total") e `List` clicável no mesmo contorno; `item(item, selecionado)` desenha a linha, `onSelecionar`. Usada na gaveta de Categorias (chip da categoria + ícone editar/check).

Depois de criar, a nova fica destacada na lista (achada pelo nome: o POST não devolve id). Clicar numa categoria da lista abre a edição abaixo dela.

- **Inicial** (`telas/inicial`):
  - Layout "G · Cards brancos": cores `--fnc-tx-*` (as mesmas da tela da conta), direto sobre o fundo da página (sem camada por cima).
  - `ResumoContas`: saudação + primeiro nome, "Minhas contas", botão de olho 44×44 e "Nova conta bancária"; abaixo um card branco com 4 colunas (patrimônio com "n de total contas no total", projetado com selo se negativo, receitas e despesas pendentes). ## localStorage

| Chave | Conteúdo |
|---|---|
| `user` | usuário logado (`AuthContext`) |
| `modoCor` | `"claro"` / `"escuro"` |
| `valoresOcultos` | `"true"` / `"false"` |
| `funcoesExperimentais` | `"true"` / `"false"`: funções experimentais ligadas (painel do usuário) |
| `ordemContas:<idUsuario>` | ids das contas na ordem escolhida |
| `ordemDashboard:<idUsuario>` | ordem dos gráficos do dashboard (`saidas`, `entradas`, `entradas-saidas`) |
| `dashboardSaldo`, `dashboardSobra`, `dashboardSoComMovimento` | `"true"` / `"false"`: botões de saldo, sobra e "Só dias com movimentação" do gráfico Entradas e saídas (`useFlagSalva` em `hooks/`; sem nada salvo, desligados) |
| `dashboardCategorias:<idConta>` | ids do filtro de categorias do dashboard: o `alterarFiltros` do Dashboard grava a cada mudança de `categorias`; ao abrir sem `categorias` na URL, um efeito aplica as salvas uma vez por conta (`restaurouCategorias`); com categorias na URL, a URL manda |
| `dashboardAtalhosIgnoradas:<idConta>` | ids das categorias que ficam como atalho de "Ignorar" na barra do dashboard (toda categoria já ignorada entra; sai só pelo X do chip) |
| `dashboardIgnoradas:<idConta>` | ids das categorias ignoradas nos gráficos do dashboard |
| `categoriasImportacao:<idConta>` | ids das categorias escolhidas na última importação de CSV daquela conta (as apagadas são ignoradas) |
| `importacaoCsv:<idConta>` | `{ tipo, colunas }`: tipo do arquivo e o nome da coluna de cada campo (título, valor, data, descrição) na última importação de CSV daquela conta |
| `ultimaConta:<idUsuario>` | id da última conta bancária aberta (seção "Última acessada" da barra) |
| `tabela:<id>` | `{ ordem, ocultas, ordenacao }` de cada `TabelaDados` (ids: `movimentacoes`, `movimentacoes-fixas`) |
| `linhasSeparadas:<id>` | `"true"` / `"false"`: modo de linhas separadas do `TabelaDados` (gravado ao clicar no botão) |
| `versaoVista` | versão do app cujas Novidades o usuário já abriu; diferente de `__APP_VERSION__` ao montar a barra (login/recarregar), o botão Novidades ganha um ponto (`Badge`) até ser clicado |

`logout()` limpa o localStorage, mas antes `guardarPreferencias(email)` (`utils/preferencias.ts`) junta todas essas chaves (menos `user` e `versaoVista`, que fica solta para não destacar as Novidades a cada login) num JSON em `preferencias:<email em minúsculas>`; o `Login` chama `restaurarPreferencias(email)` **antes** do `login`/`navigate`, porque as telas (ex.: `useModoCor` no `LayoutPrincipal`) leem o localStorage ao montar, antes do `/Usuarios/me`. O pacote é apagado ao restaurar. Pedido do usuário: deslogar e logar mantém as preferências; cada e-mail tem o seu pacote, que fica no navegador depois do logout. Testado por `scripts/testa-preferencias.ts`. Leituras e escritas ficam em `try/catch` (aba anônima pode bloquear).

## Pendências conhecidas

- Ordem das contas e preferências só no navegador; para valer entre dispositivos o back-end precisa guardar a posição.
- Arrastar com toque só pela alça (`PROPS_ALCA`, cards de conta e do dashboard); por teclado não funciona (considerar `@dnd-kit` se for necessário).
- `ResumoContas.saudacao`: `hora >= 22 && hora <= 3` nunca é verdadeiro (mantido de propósito; decisão do usuário).
- Deploy: sem o `base` do Vite, o GitHub Pages em `/financproject/` não funciona; precisa de domínio próprio/raiz.

## Como verificar mudanças

Não há testes automatizados. Para lógica pura (ex.: `utils/ordem.ts`, validações) escreva um script com `node:assert` fora do `src/` (como `scripts/testa-formatacao.ts`, `testa-filtros-url.ts`, `testa-preferencias-tabela.ts`, `testa-cor-categoria.ts`, `testa-resumo.ts`, `testa-campo-data-hora.ts`, `testa-exportar-csv.ts`, `testa-exportar-pdf.ts`, `testa-data-em-massa.ts`; rode com `node --experimental-strip-types`). Telas logadas precisam do back-end rodando; sem ele, valide com `tsc` + `vite build` e diga que o visual não foi conferido.
